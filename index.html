О проекте

Medical Diary — это self-hosted медицинский дневник, рассчитанный на мобильное использование с iPhone.

Пользователь может несколько раз в день быстро вносить показатели: глюкозу крови натощак и после еды, артериальное давление, пульс, а также съеденные продукты с точным количеством.

Каждая запись сохраняется в базе данных с датой и точным временем. Для врача можно сформировать PDF-отчёт за выбранный период.

Этот проект не заменяет консультацию врача. Он предназначен для личного учёта и подготовки данных для обсуждения со специалистом.

Возможности

Mobile-first Интерфейс адаптирован под iPhone и Safari: крупные элементы, минимум действий.
Глюкоза Учёт значений натощак и после еды в ммоль/л.
Давление и пульс Быстрое внесение систолического, диастолического давления и пульса.
Питание Записи продуктов с количеством и единицами измерения.
История Просмотр и фильтрация записей по датам.
PDF-экспорт Создание отчёта за выбранный период для печати или отправки врачу.
Docker Запуск в контейнере на Synology или Linux-сервере.
Бэкапы Резервное копирование SQLite базы данных.

Архитектура

Текущая рабочая версия использует SQLite базу данных.

Browser / iPhone Safari
        |
        v
Flask + Gunicorn Docker container
        |
        v
SQLite database in persistent volume
Файл Назначение
app.py Основное Flask-приложение
backup.py Создание резервной копии SQLite базы
Dockerfile Сборка Docker-образа
docker-compose.yml Запуск контейнера приложения
data/ Постоянное хранилище базы данных
backups/ Резервные копии
launcher.sh Единый стартовый скрипт установки и управления
MySQL в текущей рабочей версии не используется. Основная база — SQLite: data/medical_diary.db.

Быстрая установка

1. Клонировать репозиторий

git clone https://github.com/ceshbox-code/medical_diary.git
cd medical_diary

2. Запустить единый стартовый скрипт

chmod +x launcher.sh
./launcher.sh

Скрипт предложит выбрать язык:

1) Русский
2) English

Затем появится меню управления:

1) Развернуть приложение
2) Запустить контейнеры
3) Перезапустить контейнеры
4) Остановить контейнеры
5) Показать статус
6) Показать логи
7) Создать резервную копию
8) Восстановить из копии
9) Обновить до последней версии
0) Выход

Для первой установки выберите пункт:

1) Развернуть приложение

Ручной запуск без launcher.sh

1. Создать файл настроек

cp .env.example .env

Пример настроек:

SECRET_KEY=replace_with_long_random_secret
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change_me
HTTP_PORT=8000
TZ=Europe/Moscow
SESSION_COOKIE_SECURE=false
WA_RP_ID=localhost
WA_ORIGIN=http://localhost:8000
DATABASE_PATH=/data/medical_diary.db

2. Создать директории

mkdir -p data backups

3. Собрать и запустить Docker-контейнер

docker compose build
docker compose up -d

4. Открыть приложение

http://localhost:8000

Установка на Synology

На Synology должен быть установлен пакет Container Manager.

ssh root@YOUR_SYNOLOGY_HOST
cd /volume1/docker

git clone https://github.com/ceshbox-code/medical_diary.git
cd medical_diary

chmod +x launcher.sh
./launcher.sh

После запуска выберите:

1) Русский
1) Развернуть приложение

Reverse Proxy на Synology

Рекомендуется открыть приложение через HTTPS-домен.

Параметр Значение
Source protocol HTTPS
Source hostname diary.example.com
Source port 443
Destination protocol HTTP
Destination hostname localhost
Destination port 8000

Для HTTPS в .env установите:

SESSION_COOKIE_SECURE=true
WA_RP_ID=diary.example.com
WA_ORIGIN=https://diary.example.com

Использование

  1. Откройте приложение в Safari на iPhone.
  2. Войдите под учётной записью администратора.
  3. Добавляйте значения глюкозы, давления, пульса и питания.
  4. Используйте историю и фильтры по датам.
  5. Формируйте PDF-отчёт за нужный период.
  6. Передавайте PDF врачу при необходимости.

docker compose ps

Healthcheck

curl http://localhost:8000/health

Резервное копирование и восстановление

Создать бэкап через launcher

./launcher.sh

Затем выбрать:

7) Создать резервную копию

Создать бэкап вручную

./scripts/backup.sh

Восстановить базу вручную

docker compose down
cp backups/medical_diary_YYYYMMDD_HHMMSS.db data/medical_diary.db
docker compose up -d
Перед восстановлением рекомендуется сохранить текущую базу отдельной резервной копией.

Безопасность

Проект работает с чувствительными медицинскими данными, поэтому важно соблюдать правила безопасности.

  • Не публикуйте .env.
  • Не публикуйте data/medical_diary.db.
  • Не публикуйте файлы из backups/.
  • Используйте сложный пароль администратора.
  • Используйте HTTPS для внешнего доступа.
  • Регулярно делайте резервные копии.
  • Храните внешнюю копию бэкапов отдельно от сервера.
  • На Synology используйте шифрование папки или тома, если это возможно.
Медицинские данные не должны попадать в публичный GitHub-репозиторий. Проверьте, что .gitignore исключает .env, *.db, data/ и backups/.

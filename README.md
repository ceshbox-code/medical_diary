# Medical Diary

Медицинский дневник для личного использования.

## Архитектура

- один Docker-контейнер приложения;
- Synology DSM / Container Manager (Docker Compose);
- база данных SQLite внутри контейнера;
- файл базы хранится в выбранном каталоге установки в `./data/medical_diary.db`;
- резервные копии в `./backups/`;
- статические файлы подключаются из `./static/` в режиме только для чтения;
- деплой на Synology выполняется скриптом `install_synology.sh`.

## Установка на Synology DSM

Установка рассчитана на Synology DSM с установленным **Container Manager** и доступом по SSH.

### 1. Подготовить Synology

В DSM:

1. Установите **Container Manager** из Package Center.
2. Включите SSH в `Панель управления → Терминал и SNMP → Включить службу SSH`.
3. Подключитесь к Synology по SSH.
4. Перейдите в root-shell:

```bash
sudo -i
```

Установщик должен запускаться от root.

### 2. Запустить установку одной командой

Из root-shell выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/ceshbox-code/medical_diary/main/install_synology.sh | sh
```

Установщик клонирует репозиторий, создаст необходимые каталоги, сформирует `.env`, соберёт Docker-образ и запустит контейнер.

### 3. Ответить на вопросы установщика

Установщик интерактивно запросит:

- **папку установки** — по умолчанию `/volume1/docker/medical_diary`;
- **внешний HTTP-порт** — по умолчанию `8000`, внутри контейнера приложение всегда работает на `8000`;
- **доменное имя** — например `diary.example.ru`, либо оставьте пустым, если домен пока не используется;
- для домена — будет ли доступ организован через HTTPS Reverse Proxy DSM.

Пример:

```text
Папка установки (только /volume1/docker/...) [/volume1/docker/medical_diary]:
Внешний порт приложения (в контейнере порт 8000) [8000]:
Доменное имя для доступа и Face ID/WebAuthn (пусто — без домена): diary.example.ru
Домен будет опубликован через HTTPS reverse proxy в DSM? [Y/n]:
Продолжить? [Y/n]:
```

### 4. Первоначальный пароль администратора

При первой установке скрипт автоматически создаёт:

- случайный `SECRET_KEY`;
- случайный первоначальный пароль пользователя `admin`;
- `.env` с правами `600`.

Первоначальный пароль будет показан **один раз в консоли установщика**. Он также записывается в `.env`.

Сохраните пароль в безопасном месте и после первого входа измените его штатными средствами приложения, если такая возможность доступна в текущей версии.

`SECRET_KEY` пользователю показывать не требуется.

### 5. Проверить запуск

После успешной установки скрипт выведет URL и каталог проекта.

Проверить контейнер можно командами:

```bash
cd /volume1/docker/medical_diary
docker compose ps
```

Логи:

```bash
cd /volume1/docker/medical_diary
docker compose logs -f
```

Проверка приложения:

```bash
curl http://127.0.0.1:8000/health
```

Если был выбран другой внешний порт, используйте его вместо `8000`.

### 6. Доступ без домена

Если домен не задан, приложение доступно непосредственно через IP-адрес Synology и выбранный внешний порт:

```text
http://IP-SYNOLOGY:8000/
```

Например, если при установке выбран порт `18000`:

```text
http://192.168.1.10:18000/
```

Такой вариант удобен для первоначальной проверки, но для постоянного доступа к медицинским данным рекомендуется использовать HTTPS через Reverse Proxy DSM.

**Face ID/WebAuthn при такой HTTP-схеме через IP-адрес не следует считать рабочим вариантом.** Для WebAuthn используйте HTTPS-домен.

## HTTPS и домен через Reverse Proxy DSM

Если приложение должно открываться, например, как:

```text
https://diary.example.ru
```

необходимо настроить Reverse Proxy в DSM.

Схема:

```text
Браузер
   │
   │ HTTPS :443
   ▼
Synology Reverse Proxy
   │
   │ HTTP : выбранный внешний порт
   ▼
medical-diary-app
   │
   │ :8000 внутри контейнера
   ▼
Flask / Gunicorn
```

В DSM создайте правило Reverse Proxy для выбранного домена:

- **Source protocol:** HTTPS;
- **Source hostname:** доменное имя, например `diary.example.ru`;
- **Source port:** `443`;
- **Destination protocol:** HTTP;
- **Destination hostname:** `127.0.0.1` или адрес/имя, соответствующее вашей конфигурации DSM;
- **Destination port:** выбранный при установке внешний порт приложения, например `8000`.

Для HTTPS также необходим действующий сертификат для домена в DSM. Способ получения сертификата зависит от вашей конфигурации Synology и DNS.

После настройки Reverse Proxy открывайте приложение именно по HTTPS-домену.

### WebAuthn / Face ID

При установке с HTTPS-доменом скрипт автоматически записывает:

```dotenv
WA_RP_ID=diary.example.ru
WA_ORIGIN=https://diary.example.ru
SESSION_COOKIE_SECURE=true
```

Значения должны соответствовать адресу, по которому приложение фактически открывается в браузере.

Не указывайте `https://` в `WA_RP_ID`: это hostname, а не URL.

Если домен или схема доступа изменились после установки, повторно запустите установщик и укажите актуальные параметры либо скорректируйте соответствующие значения в `.env`, после чего пересоздайте контейнер.

## Обновление существующей установки

Повторный запуск установщика можно использовать для обновления:

```bash
curl -fsSL https://raw.githubusercontent.com/ceshbox-code/medical_diary/main/install_synology.sh | sh
```

Перед обновлением установщик проверяет рабочее дерево Git. Если в каталоге проекта есть незакоммиченные изменения, обновление прекращается без перезаписи файлов.

При штатном обновлении сохраняются:

- `.env`;
- `data/`;
- `backups/`.

Установщик не выполняет `git reset --hard` и не удаляет существующие пользовательские данные.

Если требуется только перезапустить контейнер без обновления исходников:

```bash
cd /volume1/docker/medical_diary
docker compose up -d
```

## Данные и резервные копии

Основные пользовательские данные находятся в:

```text
<каталог установки>/data/
```

Основная БД:

```text
<каталог установки>/data/medical_diary.db
```

Резервные копии:

```text
<каталог установки>/backups/
```

Не удаляйте `data/` при обновлении или переустановке, если нужно сохранить дневник.

Не публикуйте `.env`, БД или каталог `backups/` в GitHub или через веб-сервер.

## Перенос установки в другой каталог

Если нужно установить проект в другой каталог, например:

```text
/volume1/docker/medical_diary_prod
```

при запуске установщика укажите этот путь. Скрипт создаёт `data/` и `backups/` внутри выбранного каталога.

Не используйте для установки произвольные системные каталоги DSM: установщик намеренно разрешает каталоги только под `/volume1/docker/`.

## Безопасность

- `.env` не коммитится;
- секреты хранятся в `.env`;
- `.env` устанавливается с правами `600`;
- данные и бэкапы хранятся вне Docker-образа;
- приложение не должно публиковаться непосредственно в Интернет без HTTPS и подходящей сетевой защиты;
- для постоянного внешнего доступа рекомендуется Reverse Proxy DSM + HTTPS;
- медицинские данные являются критически чувствительными — ограничьте доступ к DSM, Docker/Container Manager, каталогу данных и резервным копиям;
- резервные копии также содержат медицинские данные и должны быть защищены с тем же уровнем доступа;
- перед удалением/переносом установки обязательно убедитесь, что резервная копия БД доступна и корректна.

## Важное ограничение медицинского назначения

Сервис предназначен для ведения личного медицинского дневника. Он не ставит диагнозы и не заменяет врача.

Медицинские данные должны сохраняться с исходными значениями, датой/временем, единицами измерения и источником данных.

## Структура каталогов после установки

Типичная установка выглядит так:

```text
/volume1/docker/medical_diary/
├── .env
├── docker-compose.yml
├── Dockerfile
├── app.py
├── backup.py
├── requirements.txt
├── data/
│   └── medical_diary.db
├── backups/
└── static/
```

`templates/` также входит в исходный проект и копируется в Docker-образ при сборке приложения.
